## Что это за проект

Тулинг для блога рецептов **ourgoodrecipes.blogspot.com**. Один скрипт
`blogger_format.mjs` (Node, ESM) тянет посты через **Blogger API v3**, парсит
сырой текст рецепта в структуру (вступление / ингредиенты / шаги / советы) и
перезаписывает пост красивым HTML — две карточки: 🥗 Ингредиенты и
👩‍🍳 Приготовление. Оригинал сохраняется ниже под пунктирной линией как
черновик (маркер `— оригинальный текст (черновик) —`), чтобы повторные прогоны
не оборачивали уже оформленный HTML (`getOriginal()` достаёт чистый оригинал).

## Команды

```bash
node blogger_format.mjs            # оформить только НОВЫЕ (неоформленные) посты
node blogger_format.mjs --all      # переоформить все (оригинал из черновика)
node blogger_format.mjs --id=ID    # один пост
node blogger_format.mjs --ids=A,B  # конкретные посты
node blogger_format.mjs --dry      # предпросмотр без записи
node blogger_format.mjs --dry --id=ID   # + сохранить preview_<id>.html
node blogger_format.mjs --backup   # из кэша posts_backup.json, не из API (не тратит токен)
```

`--dry --all --backup` — безопасный способ прогнать парсер по всем постам без
обращения к API и без записи (удобно для диагностики).

## Парсер: 3 уровня (по приоритету), см. `formatPost()`

1. **Manual override** — если id есть в `manual_overrides.json`, берём готовые
   `intro/ingredients/steps/notes` оттуда. Override заменяет ВСЁ (если задал
   только ingredients — steps станут пустыми, всегда задавай и то и другое).
2. **Structured** (`parseStructuredHTML`) — посты с заголовками h2/h3, под-рецепты,
   под-группы («Для теста»), под-шаги, блоки «Важно/Совет».
3. **Plain** (`parseContent`) — без разметки: сначала `<ul>`=ингредиенты +
   `<ol>`=шаги, иначе эвристика (строка с количеством = ингредиент, предложение
   с глаголом-инструкцией = шаг, пустая строка = граница).

`blogger_format.mjs` экспортирует `formatPost, parseContent, parseStructuredHTML,
getOriginal, OVERRIDES` и запускает `main()` только при прямом вызове — так что
функции можно импортировать в диагностические скрипты.

## Защита от порчи данных

- `posts_backup.json` — бэкап оригиналов до оформления.
- `getOriginal()` — на повторном прогоне достаёт чистый оригинал из черновика.
- `isAlreadyFormatted()` — обычный прогон не трогает уже оформленные посты.
- `DONE_IDS` (в скрипте) — посты, оформленные вручную; авто-прогон (`--all` тоже)
  их пропускает. Достижимы только точечно через `--id`/`--ids`.
- ⚠️ **Гача:** у hand-styled постов из `DONE_IDS` «оригинал» — это уже готовая
  карточка (а не сырой текст) и без маркера черновика. Прогон `--id`/`--ids` по
  ним кладёт старую карточку под черту → рецепт дублируется. Для таких постов
  оригинал держать не нужно (он = дубль): пушим только чистую карточку без
  хвоста-черновика. Так уже сделано для `7750670184181847377` (салат №2).

## Договорённости по контенту (важно для качества)

- **Количества должны быть прописаны прямо в шагах**, а не только в списке
  ингредиентов — чтобы при готовке не приходилось возвращаться к списку
  («добавьте 130 г муки», а не «добавьте муку»). Это требование владельца блога.
- Прозаические рецепты (ингредиенты вшиты в текст шагов) и посты со списком без
  количеств парсятся плохо → выносим их в `manual_overrides.json` вручную.
- Для под-рецептов с несколькими соусами в плоском списке ингредиентов
  использую префиксы («Соус: …», «Бешамель: …»).
- **Оригинал пока держим в конце статьи** (под пунктирной линией, как делает
  форматтер по умолчанию). Это временно — пока владелец не убедится, что
  ингредиенты/шаги перенесены правильно. ⏳ TODO: когда проверит — удалить блок
  оригинала из постов (всё после маркера `— оригинальный текст (черновик) —`),
  оставив только оформленную карточку.
